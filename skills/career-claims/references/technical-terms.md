# Technical-term register for STE claims

This register gives domain meanings for STE checks. It does not prove a personal
skill or give ASD approval to arbitrary words. Add a term only when the text
requires its specific meaning. Use one term for one concept.

For each added term, record its spelling, part of speech, domain meaning,
applicable rule/category and reason. Keep the scope narrow.

## Technical nouns

Rule 1.5 gives categories for technical nouns.
Rules 1.6–1.11 still apply. Do not use a noun as a verb without a separate basis.

| Term or term class | Meaning and scope | Rule 1.5 category |
|---|---|---|
| Openings, Career, Profile, claim, MASTER, application context | Named workspace or data/document objects. A claim is a stored factual statement, not an unlimited rhetorical assertion. | 19, computer science/ICT. 15, documentation |
| API, MCP, SDK, REST, source code, repository, database | Established software interfaces, protocols and artifacts. Keep exact identifiers when they identify a tool or field. | 19 |
| Product and library names. Skills keywords | Established technical names, not evidence that the owner used the product. Keep spelling and scope from the evidence. | 19 or the applicable scientific category |
| ETL, data pipeline, cursor, replay, queue, index | Data-processing concepts. A cursor records a processing position. Replay processes stored work again. | 19 |
| Durable admission, archive publication | Recording accepted work durably, or publishing retained data to an archive. Do not infer zero loss or complete source coverage. | 19 |
| Model training, neural network, classification | Named computer/scientific methods. A method name does not establish model quality or sole authorship. | 19 and 7, scientific/engineering terms |
| Accuracy, precision, confidence | Distinct statistical or model-output concepts. Use the source definition. Do not treat them as synonyms. | 7 |
| Professional roles and organization names | Established roles, persons, groups and organizations. Keep their official names. | 11 |
| Degree, award, distinction, hackathon, publication title | Professional event/qualification and document terms. Keep recognition types, issuing bodies and exact titles distinct. | 11 and 15, as applicable |
| Numbers, dates, units, quotations and labels | Exact values or fixed text. Keep units, date precision and qualification status. | 9, 10 and 15, as applicable |

These classes identify candidates for a term check. They do not authorize an
unexamined phrase merely because it concerns software or a profession.
A longer term must also pass rules 2.1–2.2.

## Technical verbs

Rule 1.12 gives categories for domain processes. Use an accurate approved verb
when it communicates the same meaning. Do not use a technical verb as a noun
without a separate technical-noun basis (rule 1.13).

| Term | Part of speech and narrow meaning | Rule 1.12 category |
|---|---|---|
| compile | Verb: translate source code into an executable or output artifact. Not a general synonym for collect. | 2(c), computer system operations |
| parse | Verb: interpret input according to a defined syntax. Not a general synonym for read. | 2, computer processes/applications |
| encrypt, validate | Verbs: apply encryption, or enforce a defined software data contract. Not generic claims of security or correctness. | 2(b) |
| train | Verb: adjust a model's parameters with data in a specified learning process. Not personnel instruction. | 2(c) or 3(a), according to the process |

Do not add *develop*, *implement*, *design* or *build* as unrestricted exceptions.
Examine the specific action. Use `WRITE`, `MAKE`, `PREPARE` or another accurate
approved construction when it communicates that action.
The CV-fragment adaptation does not give automatic word approval.
Use clear English if an STE choice reduces precision or naturalness.
